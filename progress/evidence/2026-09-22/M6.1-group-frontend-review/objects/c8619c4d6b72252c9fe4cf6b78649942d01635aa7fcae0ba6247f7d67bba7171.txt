## Spec

### P1 — access must remain valid through the private ACK persistence boundary

Normative source: PRODUCT_DESIGN.md:1160 requires “角色/Policy未知或变化清空学科payload，丢弃旧异步响应” and applies the original actor/workspace/key/body rules to replay and every execution boundary. Group numeric plans can contain private expected answers, so suppressing React state alone is insufficient for a late academic ACK.

Frozen locations:

- inputs/apps/web/src/features/authoring/useAuthoring.ts:145 checks current access and sequence once, then line 146 awaits `persistAuthoringCommand({...retained, ack})`.
- inputs/apps/web/src/features/authoring/authoringCommands.ts:62 awaits `store.load`; line 69 later calls `store.save` without another access predicate or transactional admission contract.
- inputs/apps/web/src/workbench/DraftStore.ts:129 writes the complete record; line 134 resolves only after the actual IDB transaction completes. The saved ACK contains `plan.assertions[].expected`.

Minimal actual reproduction: `repro/ack-race.test.tsx:578` uses the real current hook, command persistence and DraftStore with fake-indexeddb. The port returns the valid synthetic group numeric DTO immediately. A spy first performs the real `authoringCommandStore.load`, then delays completion of the first load after the preview returns. This pause occurs after the hook's access check and before its ACK write. Rerender the hook with `paused=true`; confirm `academic=false`; release the load; await completion. The UI's numeric state remains null, but the actual IDB record's ACK contains the private expected value 42. The required `expect(command.ack).toBeNull()` fails at line 604.

Recorded RED: 1 failed case, 69 ms case time, 572 ms Vitest duration, process exit 1. `01-red/run.log` SHA `dc929d216dac2308b9313933a7b52d50aa2a38822c0d4bd55502c57452ced9b5`; `01-red/receipt.json` binds the actual driver, command and all 35 declared input records before/after, unchanged. An exploratory identical run also failed before the recorded run. No production/test files were changed, and no browser, real workspace database, calculator or vendor was used.

Required fix direction: carry an owner/Policy/operation admission guard through academic ACK persistence and the IDB transaction boundary, aborting a write that loses admission. A check only before an awaited `load` is inadequate, and a check after an already committed `save` cannot undo the disclosure. Preserve the exact original command/key/body for explicit replay, preserve conflict detection, and keep already-sent safe cancellation ACKs durable. This review does not propose changing the ledger protocol or stripping an accepted original ACK's plan. The narrower get/put/commit scheduling window needs its own regression; it was not claimed as independently reproduced here.

The prior 31 cases cover late *network* ACK arrival after workspace/Policy replacement, but their deferred response is resolved after the switch, so the hook exits before entering persistence. They do not cover this later await within persistence. The existing broad green result therefore does not contradict this RED.

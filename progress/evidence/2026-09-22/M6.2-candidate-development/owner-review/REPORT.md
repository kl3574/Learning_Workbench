The initially reported bounded evidence gap has now been addressed in test source: while this review was being written, the implementer added `test_imported_question_identity_does_not_approve_or_publish_its_private_solution`. I read the actual added code. It stages a real learnpack, runs the actual Import worker, reads the question through Import, verifies that its candidate hash equals public metadata SHA, confirms real private solution text exists outside that public payload, and checks exact preview bytes remain unchanged after admission. It also checks that objects/revisions/solutions/reviews remain empty and only identity catalog tables change. This closes the specific source-level coverage recommendation; **execution remains unverified by this reviewer**. No test was rerun. The initial report and input pins are retained so the actual source change is visible.

The appended real pre-0016 owner-upgrade test was read only for its assertion scope: it constructs real single/practice/assessment histories, initializes the forward migration and expects the old owner payload unchanged and later admission idempotent. This review does not certify the migration logic or claim that test passed. At the initial pin point the owner test module had 12 test functions; the final file has 13. Parameterized method counts and execution results belong to the implementer's actual receipts, not this static review.

Internal trust boundary: repository.register consumes an already-resolved record and is not itself the public authorization port. The supported entry point is DraftCandidates.admit, which always revalidates the real owner. Future callers must not use the catalog alone as authenticity, permission, review or publication evidence. A frozen dataclass wrapping a candidate also does not create an approval credential.

Deferred by scope, not silently accepted: generic Draft HTTP routing, edited-draft historical payload retention, review/decision DTO and Job owner, numerical publication rules, private-solution approval binding for Import, generated-member-to-Content mapping, publication, impact adjudication and rollback remain future M6.2 work. No M6.1 or M5.4 blocker changes status because this identity slice exists.

# Independent initial review: isolated Review Jobs adapter

Fixed code: `5fefa4e9c5374306a3bd7bfbf8fd5b7e935615c1`, base `acb9e220deeaf1da7ee89ec6fda8bae9c21ca918`. The six-file diff and all 959 actual non-progress Git blobs were independently read. All four original completed gate receipts and before/after inventories match these Git bytes: 35 new tests, 50 related tests, Ruff, and mypy (186 source files). This audit does not transfer those results to any subsequent fix.

The shared extraction preserves the original two Authoring kinds, initial states and transitions. The new Review kind and transitions are isolated; typed inputs retain candidate revision and workspace/review identity; request DTOs reject client reviewer/machine verdict additions and use the safe repr/error base. There is intentionally no Review HTTP route, Quality repository, worker, durable ReviewReceipt or general JobService registration in this slice. Those missing later pieces are not presented as implemented here.

Two confirmed issues require repair before treating this adapter as a checked write boundary:

1. **Missing transaction enforcement in inherited operations.** Review.create requires a caller transaction, while inherited load/claim/transition permit autocommit operations. An actual probe called claim on a real queued Review job using `Database.connect()` with no transaction. It returned successfully and persisted running revision 2 with two events. This permits state/event writes outside the owner transaction and complete-history reads across separate snapshots.
2. **Rejected transitions can leave writes behind, including the other consumer.** The inherited transition updates jobs and appends an event before its final `self.load`. In a real caller transaction, a Review adapter given a checked same-workspace Authoring row wrote cancelled revision 2, then raised JOB_MISSING. Catching the error inside that transaction committed the Authoring mutation. A running Review→awaiting_approval request similarly made two changes before raising AUTHORING_INTEGRITY_ERROR; catching it committed an unreadable Review job. A transaction guard alone does not solve this. Consumer/current-history/transition validity must be checked before mutation, or the method must roll back its own operation on every failure while preserving the caller transaction.

The probes used only fresh temporary synthetic databases, did not edit engineering files, and reported no private input/identity values. The first private probe harness failed during Import fixture setup because it lacked a multiprocessing main guard; no Review probe ran in that attempt. That harness-only error is recorded separately; its raw stdout/stderr were not saved. After adding the guard only to the private harness, all three behavior probes ran and their exact stdout/stderr and receipt were retained. No paid model or vendor call occurred.

This initial report is immutable evidence of findings against the stated commit. A later repair must receive its own byte binding, validation and review result.

# Group Authoring browser command and hook verification

This package records focused Vitest checks of the public command journal and `useAuthoring` interface. It uses real fake-indexeddb storage and React hooks with a controlled API port. DTO wire values were exported from actual successful synthetic SQLite integration tests and are admitted by the current generated schema. These checks do not prove browser E2E operation, model answer quality, publication, or numeric execution PASS.

`synthetic-dtos.json` contains exactly detail, draft, explicit private solution, numeric preview, and safe Job values from the practice-set case in `m61-group-numeric-verification-v1/pytest-temp/final/test_question_numeric_plan_is_0/data/workspace.sqlite3`. The request's output kind was checked as practice_set before selecting the database. Only those selected DTO values were exported; sessions, CSRF tokens, provider credentials and other tables were excluded. Test-local session values are invented and are never transmitted outside the test harness.

`synthetic-command-dtos.json` contains original request/ACK pairs for prepare, numeric preview and approve from `test_approval_is_separate_job_0/data/workspace.sqlite3` in the same private numeric evidence cache. No SQLite files are copied here.

The first wrapper run collected 14 command PASS and one hook suite parse failure due to a missing async marker in the newly written test. After correcting only that marker, `red-behavior` recorded 28 PASS and two genuine storage-boundary FAIL: after a workspace or Policy change, a late group numeric preview ACK persisted its private plan into the old academic journal despite cleared projections. `source-red` preserves the exact affected product source and tests. `typecheck-initial` passed on this RED source. The earlier runner invocation with shell-default Python 3.10 failed before inputs could be captured; the explicit project interpreter was used thereafter.

The hook tests also cover explicit private-answer reads, candidate/member/ref/plan mismatches, unknown member rejection, workspace and session changes, Policy rejection, safe cancellation, and lost preview ACK recovery using the original key. Command tests cover exact original ACK persistence/replay, malformed root/member/decision receipt rejection, and genuine IDB revision conflicts without overwriting either body.

All commands use the project Node wrapper. Input inventories include tracked and untracked non-ignored repository files, excluding progress evidence. Per-run receipts report timestamps, exit status, output hash, and any concurrent input change; that broad inventory is not a claim that every listed file was executed by the focused suite.

Final GREEN: 42 PASS = 31 new group checks plus 11 existing related hook/owner/client checks; typecheck PASS. Both 937-entry input inventories unchanged. Root inserted a subject-only current/sequence guard before academic ACK persistence. The original two RED cases are unchanged; one safe-cancel late ACK positive control was added and passed. `source-initial` reconstructs the missing-async parse-failure test bytes and verifies their original inventory SHA. See summary.json for exact scopes.

# Artifact owner routing decision

Engineering decision under unchanged PRODUCT_DESIGN.md 3.0.7, SHA 2d1ecce71e0aa6953c0f772b1935e7e3abdc5933bfbbe93d851a6171236d8a4d. This note is not a new product specification.

The existing HTTP URI and binary headers stay in the existing import router. Its composition now supplies ArtifactsService with only the actual Import reader and the four existing (profile, import-job-kind) registrations. Requests cannot provide an owner or registration. ArtifactsRepository owns only the existing artifact routing lookup, scoped by exact id/workspace; Jobs supplies the actual kind through a Jobs-owned same-transaction port. A missing registry entry is ARTIFACT_OWNER_UNAVAILABLE, not a default Import owner or guessed id-prefix owner. No Quality reader, artifact, URL, HTTP operation, migration or core schema is introduced. untrusted_quality_receipt remains an untrusted Import attachment, never a Quality review or approval.

The facade opens one real transaction, reloads the actual local session, checks workspace/Policy, resolves routing and invokes the selected reader within that connection. Import.read_artifact independently requires that transaction and reloads current session/role/revocation/expiry, so direct internal use cannot rely on a stale HTTP identity. It checks current role/private Policy, the original profile's recorded source membership and manifest/blob bytes using the producer's frozen resource budget. Storage integrity errors do not return stored text or validation inputs.

Compatibility is deliberately limited: existing trusted in-process ImportService.download callers retain their prior identity-admission semantics and current Policy checks. The method is still restricted to real Import profiles/kind/source membership. It is no longer invoked by HTTP and is not the interface for future Quality consumers. Future Quality must implement and register its own reader, same-transaction current-session admission, immutable result membership and private Policy. It cannot obtain a reader merely by holding a blob or using the legacy Import method. Tests explicitly prohibit HTTP from invoking that compatibility method.

There was no generic same-transaction current-session helper in live security.py: authenticate reads by browser token on a separate connection, and author_execution_identity is an author-only worker port. current_session_identity therefore rechecks the original authenticated id/workspace in the caller transaction and returns the current role with no token/CSRF value. It has no missing-session fallback. This preserves learner access to legitimate public Import originals while rejecting stale author privileges, expired or revoked sessions and workspace rebinding.

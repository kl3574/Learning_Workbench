# Reader viewport native regression evidence

This package concerns the real Workbench 412 comparison panel displacing an existing Reader. The original controlled RED demonstrates a reachable mechanism, not a unique retrospective attribution of the earlier complete-run failure: that full run had no matching request/geometry ledger. The independent diagnosis also records an initial AF_UNIX-path harness failure and an isolated pre-fix PASS where the same panel arrived before scrolling; these do not contradict the controlled schedule. It contains only original synthetic fixture data and selected, visually inspected browser screenshots. It makes no claim about model quality, expert content approval, the full native suite or GitHub CI.

The original diagnostic controlled probe is retained privately in `m41-assessment-viewport-diagnosis/controlled`. Its source, original RED log and observations hashes are in initial-probe-green/probe-provenance.json. Replays changed only the declared source-root and output paths. Original assertions, the 5-second viewport expectation and the 30-second case timeout were not edited. The original diagnostic's genuine 412 was held and then delivered after the original scroll action. The original RED was 1 FAIL; the initial application fix replay was 1 PASS in 7.2 seconds. The independent focused-control review then found that blindly preserving the screen coordinate of a previously visible focused control can hide it behind the shortened pane. The unchanged eleven-case React lifecycle test produced 10 PASS / 1 FAIL and then 11 PASS after the focus guard; before/after helper, test and Shell bodies/hashes plus the original command logs are included. Those jsdom tests control geometry and are distinct from the later real-browser focus case. With the later focus guard, that same controlled probe was again 1 PASS in 7.0 seconds.

The first four-case run on the focus-guard source was 3 PASS / 1 FAIL in 28.6 seconds: the unchanged Assessment first case, unchanged held-resize case and new enabled-input focus case passed. The submitted new case failed before its controlled gate because setup had already produced a real session conflict. This is a setup failure, not a target viewport RED.

The next new-two-case run was 1 PASS / 1 FAIL in 36.1 seconds. An explicit user choice resolved the earlier setup conflict, but a resize/scroll-only setup did not produce the new session PUT needed by the controlled schedule before the 30-second test limit. No new controlled viewport assertion was reached and no geometry receipt was emitted before worker disposal. The application and native bytes were unchanged during that run; the root agent appended an ADR paragraph, recorded as the only before/after source difference.

A real active-tab pin toggle then provided an explicit session mutation. Two new cases passed in 13.6 seconds. Actual visual inspection found the submitted explanation mostly clipped despite passing the inherited default intersection assertion; this limited PASS is retained and is not presented as proof of complete text visibility. An added full-paragraph pane-bounds assertion then failed: paragraph top 485.125 was above the new pane top 493.46875. This is a real failure of the stronger assertion in the centered fixture geometry, distinct from the original five-second regression.

The final submitted case uses real mouse wheel input to place the whole explanation at the lower Reader position corresponding to the original regression before executing the original scrollIntoViewIfNeeded and delivering the real 412. It retains the stronger full-paragraph assertion and passed in 8.3 seconds. Paragraph geometry changed from 760.65625–816.65625 to 761.125–817.125 inside the new pane 493.46875–818. The real comparison stayed open and no choice was made after the controlled response. The server session, original submitted Attempt, saved answers and ungraded result were read back unchanged.

The enabled-input case passed on the same application and shared-gate bytes in the preceding two-case run. Its original focused input was at 174.46875–247.0625 inside pane 94–818 with scrollTop 944. After the real comparison it remained the same enabled activeElement at 493.9375–566.53125 inside pane 493.46875–818 with scrollTop 1024. The case checks that its original input bottom is above the new pane top, so unguarded full compensation would have hidden that focused input. Its complete body and shared setup/gate were byte-identical to final; hashes are in lower-pane-final/carried-focus-scope.json. It was not rerun after the later submitted-case-only geometry change.

The final submitted-case run's 504-source before/after hashes match. Final source is frozen for root acceptance; this package does not claim a single combined final four-case execution.

All runtime directories were under the short home-cache TMPDIR, not /tmp; RestartRuntime allocated new independent loopback ports and original synthetic workspaces. Test sources/configs are archived with .txt to avoid test or lint discovery. Only private absolute-path strings are normalized in text; each manifest entry preserves distinct original and published SHA256 values. RUN_BINDINGS.json binds each run to its actual helper/test/source hashes; a base HEAD alone does not include the untracked implementation patches. Native runs have no invented start timestamps; imported record_check timestamps retain their original command-clock meaning. Raw DOM error snapshots, SQLite databases, browser profiles, bootstrap capabilities and credentials are excluded. The manifest aggregate is SHA256 of each sorted path + NUL + published SHA256 + LF; it excludes MANIFEST.json and publication-scan.json.

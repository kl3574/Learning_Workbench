# M5.2 Reader cold recovery delivery experiment

Actual result: **2 PASS (13.5 seconds)** on fixed software commit `3dd75f01966bb5dcf0b9ea0855e6b82ce335d814`. This experiment did **not** reproduce the original CI failure and does not establish its cause. No product code, native timeout, original historical-case business assertion or retry setting was changed. All 783 tracked non-progress source files in the fixed mirror had identical before/after bytes; the mirror itself is not duplicated here.

The immediate and controlled cases each used a fresh synthetic RestartRuntime, sequentially, with identical fixtures and original bootstrap/import operations. The first real workbench GET body was 206 bytes and SHA `3b14c9e913a15a9f41db4af251715e208aaa49e840609198eb18726f9cbaff18` in both runtimes. The complete HTTP headers were not identical: ETags bind different workspaces. The controlled response was held about 19.8 ms until the recovery heading and two real session JSON completions were observed; it was delivered unchanged, without deliberately crossing the original 5-second Reader assertion. The immediate branch may already have had the same natural response order. These two cases do not cover a complete inversion of all startup orderings.

The original first assertion passed in both cases with a real r2 Reader. Final snapshots show `real_reader_count: 0` because the full original case ends with an intentionally bad historical hash and checks its explicit refusal while preserving the r2 server session. This final state is not the original CI first-assertion failure.

`pre-registration/` retains the initial hypotheses and its contemporaneous scope. `run-001/run.log`, execution receipt, raw per-case observations, byte-identical real workbench JSON in `.bin` files, and review are actual run records. The log is preserved byte-for-byte, including any ANSI or runtime warnings; no failure was removed. `source-before.json` and `run-001/source-after.json` retain all 783 paths/hashes. `harness/` holds the exact exercised observer and mapped helper sources as archival `.txt`, the original historical body, and mechanical diffs. Removing the two added observational calls recovers the original body exactly; the whole original test file was not executed directly. `original-case-observer-only.diff` was added after execution and is not included in the execution harness-unchanged claim.

Each manifest entry records its raw source alias/path, original absolute-path hash, raw/public byte counts and SHA, and every fixed-prefix replacement count. Public content changes are limited to the declared acceptance-cache, workspace, and short-TMPDIR prefixes. `${ACCEPTANCE_CACHE}`, `${WORKSPACE}`, `${SHORT_TMPDIR}` are publication aliases, not executable paths. Original files remain untouched. Existing internal receipt hashes refer to raw bytes; the package manifest supplies the public-byte relation. Source suffix changes `.ts` to `.ts.txt` are path-only archival mappings. No database, browser profile, credential, screenshot, compiled cache or full source mirror is included.

This package is a derived public candidate only; it does not rerun tests or claim new CI success. The current repository scanner exports `inspect(path, data)` and has no `inspect_file`; the packaging audit calls that actual function on every candidate file's bytes using its intended public path. Scanner source SHA and result are in the manifest; manual provenance limits still apply.

Aggregate algorithm: entries sorted lexicographically by public `path`; form `[{'path': entry['path'], 'sha256': entry['public_sha256']}, ...]`; `json.dumps(..., sort_keys=True, separators=(',', ':'), ensure_ascii=True).encode('utf-8')`, no trailing newline; SHA256 of those bytes. Manifest is excluded from aggregate; it is separately scanned and hashed.

## Spec and internal contract

### P2-A OPEN: same-workspace decline has no permitted way to read its basis

Proposal lines 253/341 allow valid learner/author, including an independent/open-book control context, to decline without reading academic content; line 253 says the UI can act from `control.approval_ids`. But `CodexTurnControlView` lines 178–187 contains only approval IDs, while the only `GenericApprovalView` read is restricted to current author/academic permission (line 253). The reused core `ApprovalDecision` requires both `operation_sha256` and `expected_revision` (sole specification lines 2703–2706); line 255 requires the actual approval revision.

Counterexample: actor A creates a pending operation, then a fresh learner actor B in the same workspace opens the control page. B can read the approval ID and is explicitly eligible to decline, but cannot read the exact SHA/revision. Guessing r1, inventing a hash or requiring A's prior browser cache cannot implement the declared flow. Interrupt remains a separate available stop path, not evidence that per-operation decline works.

Necessary narrow correction: a closed, no-content approval-control projection in an already approved safe control view, containing enough actual identity/revision/hash/state to construct the original decline request; exact membership and ownership must be checked. It must not expose command text, file names, patches or grant approve/start permission. Acceptance: fresh B with no A cache reads the safe basis, declines once with the existing strict body, receives an ACK attributed to B, and never reads the academic approval view or starts an operation. Stale revision and altered SHA remain rejected.

### P2-B OPEN: same-workspace revoke has no discoverable consent/CAS basis

The new revoke path requires consent ID plus expected revision (line 154). The only `CodexConsentView` (125–130) embeds the full frozen academic summary (98–113), so it is not a safe learner/independent read under line 341 and sole specification 1024. The safe turn control (178–187) contains neither consent ID nor its current revision. The preparation read includes original message/refs and is likewise not a substitute no-content control read.

Counterexample: after A grants a consent, fresh learner B discovers the turn through the safe list. B is explicitly allowed to revoke but cannot discover the consent or acquire its exact CAS basis without the prohibited summary or A's private page state. Guessing initial revision would also fail after an actual revoke. A generic interrupt does not fulfill the separate declared revoke behavior.

Necessary narrow correction: a closed, same-workspace consent-control binding in the existing safe turn projection, retaining consent ID/current authorization revision/state needed for revoke. No full summary, references or scope disclosure, and no grant/start authority. Acceptance: fresh B can revoke from the safe record; changed CAS, cross-workspace, unrelated consent and duplicate-command cases retain their specified semantics. Original grant ACK remains historical.

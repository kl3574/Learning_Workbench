## Implemented boundary

Five registered closed, typed endpoints: preparation POST/GET, decision POST, session POST/GET. Writes bind current author/actor/workspace/Policy, Origin/CSRF, full body/key/CAS; reads are current authenticated metadata-only, query-only and no CLI. Forward migration 0027 adds the Codex preparation/event/head/command/membership owners and uses the existing session projection. No core DTO, old migration, provider consent, model, account/login, turn, tool or artifact permission is added.

The private operation freezes complete ordered control requests, precise binary, configuration, stable Broker permissions, runtime/deployment closure, schema versions and resource policy. Approval is a single decision; consumption/permit/initializing record are atomic. Execution is outside the DB transaction, held by a named process lock. Facts are saved before current delivery authorization is rechecked. Original ACK, current GET and external uncertainty remain distinct. Full workspace history, heads and independent memberships reject missing tails/all rows rather than rebuilding them. Recovery never starts a process; active owners are not reclaimed.

`profile-v3` retains the same request bytes, resource limits and external fence. The complete fixed upstream schema now validates the three returned control metadata fields and exactly one `thread/started` notification bound to the same complete empty thread. Unexpected, duplicate, mismatched, late or over-budget output remains a failure/unknown. Original v1/v2 schema/receipt decoders are retained; current deployment changes cannot consume old approval. Runtime success does not mean account authorization, running process, academic validation or full Broker support; all three public capability flags remain false.

## Limits and next integration boundary

This package does not include full Python, Web/UI, native browser or full Broker acceptance. The UI owner and root own combined native/full gates and backup/recovery tests; their counts are not represented as execution by this agent. The actual control stage used application reconstruction, not a separate API OS-process restart. Earlier `ad494` full Python ERROR/native FAIL are not reclassified by any result here. No rejected system-extension probe or old UI diagnostic was restarted.

No global credentials/config, real user DB/key or raw account response was read/copied. Test-generated private DBs, signing material and Broker state are retained privately and excluded from manifests intended for sharing. No model/turn/tool/login/account request was sent, no network capability was granted, and no arbitrary RPC was used. Offline schema generation is a separate engineering action and is not a session capability.

Only explicit `SAFE_SHARE.json` entries are public candidates. Original evidence bytes remain unchanged. Public candidates replace the exact byte prefix `$HOME` with `$HOME` only, with both raw and candidate SHA/size recorded. No DB, archive, credential file, raw thread response or complete private freeze/profile is allowlisted. Automatic scanning supplements the explicit source/field review; it does not guarantee arbitrary prose privacy.

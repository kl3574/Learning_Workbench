# 0028: Explicit reviewed Import block publication

PRODUCT_DESIGN.md §§7, 9.3, 15.1, 20.1, 20.3, 20.8 and Appendix A define owner ports, immutable publication, exact candidate approval and a four-field publish request. This slice implements the application service; HTTP/UI registration is separate.

Only a real pending, learner-visible, explicitly markdown/text Import may supply one original text block, metadata revision 1, with an absent original Content ID and no base/concept/dependency/private solution/symbol/asset scope. The actual original source and parsed body have separate hashes; text parsing may wrap the body. The current author must explicitly have supplied mathematical N/A with reason and source APPROVED. Current complete Quality history, structural PASS, actual warnings and owner material are revalidated. Machine math/source/teaching NOT_RUN is retained; no Provider or numeric execution occurs here.

An independent publication lifecycle adopts the exact candidate now, then records draft→in_review→approved→published in one writer transaction. These describe the present selection/revalidation/Content operation, not fabricated past Review jobs or new human approvals. Its internal revision is separate from immutable candidate revision and Review receipt revision. The publish request selects one Review; no global latest-Review reduction exists. Producer DTOs/rows and the original Import.commit algorithm are unchanged.

Content owns new-object absence CAS, blob durability, immutable revisions/body references, current pointers and outbox/invalidation. Import owns current pending eligibility and original material; Jobs supplies actual job identity/input/status/cancellation facts through its application port. Provenance freezes precisely the original block/source relation. Publication owns the lifecycle, immutable events, permanent actor/route/key request/result and candidate→Content mapping. The entire operation rolls back on any failure; no record JSON grants authority.

Same-key replay authenticates current access, all current Quality history and recursive physical evidence, the exact original approved receipt revision, every original admission condition, original Import Job/input/source/body and published Content/provenance. It returns an already committed historical ContentRef even after a later legitimate human rejection, a new Content current revision, or real Import cancellation/mapped commit. New commands still require pending Import and cannot publish the same candidate twice. The ledger does not expire with the generic 24-hour idempotency cache. Different actors cannot inherit an old actor's ACK.

Publishing the original block intentionally occupies that Content ID. Later unchanged Import.commit returns its existing ID-collision error. Explicitly mapping just the conflicting object ID to a fresh ID lets the existing importer rehash its whole parent graph and finish. The copied block may share body bytes but has a distinct exact ContentRef and receives no publication/Review approval by shared hash, citation or Import ID. The original import receipt remains NOT_RUN. Canceling the original Import only changes its own producer/job state, not immutable published Content.

Tests use real local Import/Review workers, SQLite, BlobStore, source/Content reads, current assessment Policy, concurrent connections and injected storage failures. Human decisions and content fixtures are explicitly synthetic. Tests preserve implementation defects separately from fixture/setup and static-check failures. This slice does not implement a global Draft state GET, editing/needs_changes workflow, mathematical/generated/question/private-solution/group publication, existing-object updates, publication UI or overall M6.2 acceptance.

# ADR 0031: Read-only exact block revision comparison

PRODUCT_DESIGN.md §§6/15.2, 20.1 and Appendix A require immutable references and meaningful version comparison. This narrow Reader feature compares two explicitly selected historical revisions of one actual block. It does not edit, approve, publish, restore, or derive semantic equivalence. Four main navigation entries and existing Reader/note actions are unchanged.

Only already-registered session, history, exact metadata/provenance and body GETs are used through the generated client. Current OpenAPI shape validation is reused; the feature checks block identity, exact ETag and projection reference, actual complete ContentBlock metadata hash and UTF-8 re-encoded body hash. Metadata canonicalization is restricted to this closed fixed-ASCII-key model and safe integer revisions, including all persisted default fields. It is not a general cross-language float canonicalizer. The existing text transport exposes decoded text, not an independent original-byte download; decoding changes (including BOM loss) fail hash checking. Provenance's ETag identifies block metadata only, so provenance remains the current authorized server projection, not independently signed approval. No new review_state vocabulary is introduced.

Selection ownership is workspace+block ID, distinct from that block's current revision. Explicit choices survive collapse within the mounted page; body results are discarded on collapse, selection change, error, target/workspace/access change or visibility/focus invalidation. A current session/Policy basis (without storing credentials) is checked before and after reads. Displayed results alone use sequential two-second permission checks; a check still unresolved after two seconds clears content, as do failure and changed role/Policy. Late asynchronous completion cannot repopulate another owner/selection/access generation. A browser profile outside the access broadcast is observed by these actual permission reads; instantaneous remote push notification is not claimed. Current protection is enforced by the server for every GET.

The comparison computes common complete-line prefix/suffix and marks the entire changed middle. Runtime and memory are linear, no quadratic LCS. Above a total 100,000 UTF-16 units or 2,000 lines, only intact original text is displayed side by side. No trim, Unicode normalization or mathematical simplification is performed. Long source lines scroll within their container. History paging is explicit and bounded to 200 options per current listing, with remaining history clearly noted; this is not a claim of complete history when truncated.

Behavior tests distinguish transport/shape/hash rejection, explicit selection, asynchronous owner changes, current Policy and bounded text changes. The permanent native case imports existing synthetic r1/r2 Reader history through the actual Import application, then compares over real HTTP and checks desktop/narrow containment and no learning/domain mutation. Synthetic reference import is not human mathematical approval. Each actual execution and any retained failure is recorded separately in private evidence; this ADR does not claim gates have passed.

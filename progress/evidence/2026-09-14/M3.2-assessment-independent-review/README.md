# M3.2 独立后端审查

本包是一次有界独立审查及修复复验。它不等于完整 M3.2 阶段验收，也不替代根任务的固定提交完整门禁。

原样保留的 7 个真实 SQLite/service 探针，修前 **3 FAIL / 4 PASS（1.96 秒）**，修后独立重跑 **7 PASS（2.03 秒）**。原有 3 个失败都来自幂等回执没有绑定冻结作答：旧创建键可被损坏的缓存指向另一个活动作答，缓存题面或引用哈希改变也会直接返回。故障注入仅在测试中直接修改 SQLite；不声称正常 API 允许任意修改数据库。

修复采用不可变回执实例绑定，同时核对真实作答与缓存公开字段。实例过期删除时绑定随外键级联删除，保留幂等键正常重用；历史 revision/status 回执没有被改成当前响应。审查者回读了修复，未修改后端实现，使用未改的 7 个探针完成复验。跨操作最后保存/提交竞争，以及评分 outbox 三种绑定损坏检查均通过。限定范围内没有剩余发现。

五个修前后端源码完整副本、五个修后副本、同一个测试源码与可重放 runner 均以 `.txt` 保存。修前五个后端文件、修后六个源码/测试文件在相应运行前后哈希一致。共享依赖和其他模块当时仍在开发，不能把这些局部稳定哈希冒充整个分支的固定提交验收。

所有输入来自仓库原创合成练习/测验样例和隔离测试 SQLite。没有复制数据库、真实学习资料、浏览器 profile、DOM 或 capability 值。原始本地日志保持不变；公开派生只脱敏个人/临时目录、运行时地址及出现时的秘密值。manifest 明确区分原始 SHA256 与公开派生 SHA256；各 receipt 内的 raw hashes 仍指原始内容，公开文件校验使用 manifest 的 published_sha256。

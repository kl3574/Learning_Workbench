# ADR 0008 — Reader、笔记与精确来源的持久化

需求仅来自 `PRODUCT_DESIGN.md` 3.0.0，尤其 R-04/R-09/R-10/R-19/R-38、§4.3、§10.4、§20.1 和附录 A。本记录说明实现选择，不增加产品规范。实现与验收状态以 `progress/state.json` 和带源码哈希的证据为准。

课程目录读取冻结的 Course → Lesson → Block 元数据及真实学习动作投影，不读取正文或进行全文检索。目录搜索只在指定课程修订内匹配标题及真实祖先标题；无 sections 时使用课程自身分组。Reader 分别核对对象的 metadata ETag、完整 ContentRef 和正文 SHA-256；旧修订保持可读，不用 current 替换旧标签。例题是教材中的 worked_example 块，其他块的精确定位不冒充例题。

附录 A 的八个实际路由由已实现的 handlers 生成严格 OpenAPI/TypeScript：目录与目录搜索、笔记四项 CRUD、学习进度与动作。既有 `/blocks/{id}` 默认仍返回 ContentBlock；显式 `include_provenance=true` 返回严格来源投影，采用具名 RootModel 联合，保持核心 54 个模型和 102 项目标路由不变。ETag 标识块元数据，包含角色权限的投影使用 no-store，每次重新检查权限，不因相同块哈希返回旧角色的 304 表示。

新增迁移 `0002_reader_provenance.sql` 在导入确认的同一事务冻结 workspace + block revision/hash 对应的原件、Citation 与诊断。表的复合外键核对正式修订，触发器限制工作区/来源一致性并禁止更新。Citation 的外部来源哈希与导入容器的哈希分别保留；相同 Citation ID 不跨导入查找。`original_source` 独立呈现真实保留原件，即使合法内容块没有 Citation，也不伪造引用或丢失原件入口。原件下载仍走现有受控来源/附件端点，访问权限随当前会话重新检查。

旧来源恢复仅由明确的启动入口执行，GET 不解析原件或写回数据库。恢复必须重读校验过的原件，以冻结预算重新解析，核对候选 metadata hash、实际确认决定、ID 映射和最终发布块。存在一条旧幂等回执，不能证明另一份收据中的映射属于该决定。新导入回执保存严格 `commit_request` 原文，保留数组顺序以复算原决定哈希；较旧回执没有原始顺序，若无法精确重构原哈希，则保持 unresolved，不猜顺序、不选任意来源。原件缺失、映射歧义和无法证明的旧目标课程转换逐条保留诊断，不阻断其他可验证的恢复。

笔记的 Selection 始终锚定具体块的原始 Markdown，偏移为 Unicode 码点的半开区间，并核对 quote、prefix/suffix 和完整目标引用。新锚点仅接受具有可验证正文的 ContentBlock；其他对象返回明确错误。渲染选文按实际 DOM Range 与源位置对应，重复文本按实例处理；无法证明的渲染转换或跨块选区使用明确错误及原文选择回退，不推测偏移。

笔记创建、修改和软删采用幂等命令；PATCH/DELETE 的 If-Match 必须等于旧不可变修订哈希。发布事务先冻结所有旧 current 引用，全部内容指针推进后，再为确实受影响的当前 exact 笔记追加一次 stale 修订；旧笔记及原锚点哈希保留，不把动态 stale 状态伪装成旧 metadata。副作用与内容发布、索引、outbox 同事务提交或回滚。笔记 current/revisions 只通过显式开放且受相同工作区和独立测试 guard 保护的端口读取。

阅读与书签来自用户明确动作，浏览、滚动与笔记内容不认证掌握或成绩。应用内严格 StoredUserAction 保存真实 kind/value，服务器生成事件 ID、时间及来源；不扩充核心 LearningEvent 枚举，也不把 bookmark_set 冒充 read_marked。空进度 GET 不插入事件或投影。笔记创建记录既有 note_created 事件；其他学习行为只更新其对应投影，不抹除历史证据。

学习进度的 `course_id` 查询没有修订参数，范围为该课程全部已发布修订的精确成员。每条 Course/Lesson/Concept/Block 引用均验证 entity、id、revision 和 hash；不以 current 成员排除旧章，也不以裸 ID 包含从未入课程的新修订。过滤不改变返回引用或全局 CAS revision。笔记创建等真实事件令进度版本改变后，Reader 刷新投影；412 读取最新状态并要求用户再次明确提交，不自动重放写操作。

中央标签身份保持 §4.3 的 view_kind + object_id + revision + mode。同一身份收到不同的冻结对象或父引用时，导航检查使用最新会话并明确拒绝，原标签、课程和草稿保留；不扩展标签身份来掩盖冲突。单独的已定位标记区分首次锚点跳转与真实保存的滚动位置 0。受控原件在字节核验后重新读取权限，并结合页面生命周期和跨页面访问状态失效，阻止角色变化后的迟到下载。

浏览器本机笔记草稿与正式服务端笔记分别保存：本机 IndexedDB CAS 负责并发候选和故障保护，服务端修订/hash 决定正式写入基准。真实恢复验收使用独立合成工作区、持久浏览器配置和受测试拥有的后端进程，关闭实际浏览器后停止并重启 API，再通过只认证、不清理会话或缓存的入口回读。测试不能以重新初始化状态、内存服务或合成 UI 示例代替正式 Reader/笔记回读。

笔记的稳定 ID 不因重新绑定内容块而变化，冲突恢复按该 ID 在当前工作区读取最新笔记，不以旧锚点过滤掉新版本。冲突界面同时提供正文和原基准／本机／服务端锚点的比较。软删除服务端笔记不授权丢弃本机未同步续写；续写仍可恢复，服务端当前视图缺失则明确提示，历史引用保持可读。

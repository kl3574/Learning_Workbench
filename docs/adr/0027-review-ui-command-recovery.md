# 候选审核前端与原命令恢复

依据 PRODUCT_DESIGN.md 3.0.7 §4.3、§12.4、§19.3、§20.2–20.3。新功能位于 draftReview；既有评分复盘 review 目录保持独立。创作与导入仅提供明确打开入口，使用现有生成客户端及实际审核、Jobs、Artifacts 路由；不新增或手改服务端、契约、通用 transport。

创建审核、人工决定和取消先将完整原 key、body、候选基准写入 DraftStore，再发送真实请求。存储失败不发送；未知结果保留原命令，不自动生成第二个创建或决定。原 ACK 与另行 GET 的当前任务、回执分开展示；拒绝保存原 CAS，不自动改基准。严格解码包含未知字段拒绝、准确候选/工作区/审核 ID、决定相邻版本及原理由关系。两个页面保存冲突时保留全部原件，不能覆盖不同命令或不同 ACK。

当前 SessionResponse 没有可证明刷新前后同一 actor 的身份字段。随机页面标记与当前访问代次仅用于限制当前页面内的显式原 key 回放，不是认证证明；不保存 CSRF、凭据或其摘要。刷新、重新 bootstrap 或访问代次变化后，旧未知创建/决定保留只读，已知 Job ID 可重新读取当前状态。旧未知取消也只读保留，但不能永久堵塞安全停止：用户实际读取当前 Job 后，可明确按当前修订发起新的取消 key。这是新控制命令，不是冒充原操作者回放；该例外不扩展到创建或决定。

受保护内容按 workspace/访问代次/Policy 隔离，异步晚到响应不能进入新上下文，撤权立即清空页面中的候选表单、回执、报告和临时下载 URL。安全 Job 控制仍可读取和取消。Job 轮询绑定选择代次和请求顺序；显式读取或改变当前 Job 的命令先失效旧选择，在成功与失败后重建相应轮询，禁止旧定时器覆盖或读取已离开的 Job。

未提交表单仅保存在当前面板内存，创建表单绑定完整候选，决定表单绑定审核 ID、回执版本及完整候选；暂时卸载、换候选或重新读取不丢原值，不把旧理由带到新基准。权限刷新需要明确放弃临时表单；关闭由 Shell 确认，页面卸载提供浏览器提示。实际 Policy 或身份撤销不受这些确认阻挡，恢复后表单为空。明确提交的原命令则继续按原持久记录恢复。

数学、来源选择均无默认批准，必须原理由与独立确认；reviewer 由真实服务端会话给出。报告只能取当前回执包含的受控路径，核实际 Blob 字节与强 ETag 后再次读取相同当前回执，才展示文本或下载；原报告文本只作惰性 details 展示。机器及独立教学边界保持 NOT_RUN。候选 DTO 仍返回 draft，页面明确区分该投影与审核回执，不虚报状态推进、发布或完整 M6.2。

合成行为测试、真实本机浏览器流程与真正人工内容审查分开记录。浏览器测试使用隔离工作区与动态端口、真实 Import/Review/Jobs/Artifacts，模拟的仅是丢失实际响应；不调用模型。合成双 REJECTED 决定不代表用户或专家内容验收。发布、影响分析、版本对比及教学验收依赖后续实现与独立批准。

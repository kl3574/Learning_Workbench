# 0022 — Review inputs and Jobs ownership

M6.2 implementation decision under PRODUCT_DESIGN.md 3.0.7, sections 6, 11, 18.4, 20.1 and Appendix A. This records internal engineering choices; it does not add product requirements or certify review/publication.

Review reads the registered candidate's actual owner in the caller's transaction. Complete immutable material and numeric observations are separate values: later decisions, execution progress and expiry cannot replace an earlier observed record. Numeric verification checks the original ledger prefix and current author/Policy/Provider history. A self-consistent descriptor is not proof that a review occurred; the future Quality history must persist and authenticate that binding. Import has no numeric owner pipeline and its public candidate excludes private solutions, neither of which establishes mathematical inapplicability.

The review request models use exactly the Appendix-A fields. Requested checks are nonempty and distinct; a human decision requires a nonblank reason and distinct evidence IDs, with an empty evidence list allowed. These are input validation choices, not automatic approval rules. The models retain original text while hiding academic content from repr and validation error strings. They do not register routes; HTTP/client generation is part of the subsequent real application integration.

The internal `draft_review` Jobs adapter reuses the existing checked event, lease, CAS and cancellation implementation through explicitly isolated consumer kinds and transitions. Existing Authoring adapters still accept only their original two kinds. Review starts queued and permits no `awaiting_approval` transition. Its typed input binds the actual Job ID to the intended Review ID; no ContentRef or ReviewReceipt is invented. The future Quality owner must recheck current permissions and exact material before creation, execution, replay and protected reads.

Review lifecycle reads and mutations require the caller's transaction. A transition reloads its own current consumer row before any mutation and rejects a stale row or invalid transition. A local SQLite savepoint rolls back a malformed result/lease and its event even if the caller catches the exception and commits its wider transaction. This preserves unrelated outer writes and prevents a borrowed Authoring row from being mutated through the Review adapter. The original Authoring lifecycle behavior and diagnostics remain compatible.

This foundation has no Quality revision repository, machine-report artifact, worker, HTTP route, author decision or publication flow. Generic Job routing deliberately remains unavailable for this kind until its actual owner is integrated. The next vertical slice must persist the real review input and immutable revision/command/evidence history, run actual local checks, deliver a protected report, and only then produce the exact ReviewReceipt. No constructor, queued Job, machine result or future pair of human verdicts independently grants publication permission.

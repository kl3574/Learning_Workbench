# M5.2 回归修复的事务与前端生命周期边界

本记录落实唯一规范 `PRODUCT_DESIGN.md` 3.0.3 的权限、持久状态与有界后台维护要求，不增加产品需求。实际执行状态与原失败证据见 `progress/M5.2-next.md`；本文不证明 CI 已通过。

推荐维护的空闲判断先在独立只读事务中核验现有完整历史、重试时间、输入与依据。确认本次无需更新时直接退出，不取得 SQLite writer 保留锁、不写状态、不向客户端交付读取结果。缺状态或需要更新时退出旧快照，在原 `BEGIN IMMEDIATE` 事务中完整重做权限、历史和输入核验，再按原逻辑登记、计算与原子发布；不得把预检的数据带入发布。并发来源变化可能延后到下一 tick，但它在来源事务登记的 dirty 代次必须保留。失败记录仍走原受当前权限保护的写事务。

该选择只缩小无更新维护的持锁范围。Content/Reader 读取与测验启动共用的现有排他保护、真实发布事务、完整性校验均保留。累计合成库的实测说明无更新维护会造成读取等待，未证明它是 GitHub Reader 秒级超时的唯一原因；原浏览器断言与超时不因此调整。

前端 Policy 读取区分明确权限失效与后台轮询。明确刷新/焦点变化仍推进权限 epoch 并撤下旧可用状态；同 epoch 内按已完成请求序号采用结果，允许较早请求在较晚请求仍挂起时恢复初始状态，同时拒绝覆盖较新已完成的成功或错误。轮询继续运行，服务端各操作的权限检查仍是授权依据，客户端序号不冒充实时权限证明。

推荐导航在布局 effect 中更新既有失效 guard，使 DOM 首次呈现可用按钮时，guard 已与该次提交的工作区、Policy 和上下文一致。检查返回后的完整引用、父链及本机未保存状态验证保持原逻辑；迟到结果仍须通过既有 guard。受控生命周期反例与原 CI 观察分别记录，不把局部反例追认为没有相应时序证据的历史 CI 唯一原因。

顶部导入入口与原 `openAux` 守卫共用 `subjectLocked`：Policy 尚未就绪或独立测试生效时禁用入口，并说明原因。权限恢复只恢复入口，不自动重放曾被拒绝的点击；已打开导入窗口仍由既有 Importer 权限暂停逻辑保留选择、隐藏受限材料。真实 Shell 下暂缓实际 Policy 响应的同一浏览器测试已观察到原入口可点击而守卫拒绝的反例，修复后通过；另以真实独立测试开始和明确放弃核验窗口、文件与格式保留。原 Reader 用例字节及超时不变。该受控反例证明入口与守卫曾不一致，未追认为缺少点击时网络记录的历史 CI 唯一原因。

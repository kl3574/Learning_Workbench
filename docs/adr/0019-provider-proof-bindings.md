# 完整输入证明的目的地与请求格式绑定

依据唯一 PRODUCT_DESIGN.md 3.0.5 的第20.5章与附录D。本文件记录实现选择；实际实现、测试与发布状态分别见 progress。

原注册表只按 adapter 与 model 查找证明。相同模型名配置到另一合法地址、端口或路径时，原证明仍可匹配。生产注册表当前为空，因此该缺口尚未放行生产请求；在注册真实模型前，需要使证明的适用范围成为实际执行的准入条件。

Provider 使用传输层相同的本地 URL 解析规则，核对目的地策略、协议、主机、有效端口、基础路径及最终请求路径。证明同时冻结实际模型版本范围、格式与检查器版本、容量和失效依据，并参与 proof SHA。配置与浏览器不能提交可信证明。可信注册更新或失效会阻止新的准备、批准与派发；原提案、许可和终态仍保存原字节，历史回读继续核所属身份和当前读取权限。

首个文本 Responses 格式显式加入 reasoning.effort=none。该字段在完整请求计量及哈希之前冻结，格式变更推进版本并使旧证明无法授权新请求。该决定不开放思考内容展示、工具、图像、搜索或 Chat 参数兼容别名。测试服务以实际分配的确切地址注册人工规则，生产注册表继续保持为空。

公开转换器与词表可以接受离线代码、格式和计数审计。托管端点的实际预处理与该固定转换之间仍须有完整等价或严格上界依据；下载、构建、合成测试及事后 usage 均分别记录其适用范围。缺失依据时保持不可调度，不通过任意安全余量补齐未知开销。

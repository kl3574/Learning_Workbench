# ADR 0020：例题候选与独立数值检查

状态：已实施，最终验收及审查状态见 progress；任务 M6.1。
依据：唯一规范 PRODUCT_DESIGN.md 3.0.6，§20.8、附录 A/D。本记录只解释实现选择。

## 准备、授权与候选

AuthoringContext 经 Content 公开端口读取准确块版本及完整正文，在创建事务中冻结输入、原引用和准备快照。AuthoringRepository 与 AuthoringJobRepository 负责自己的记录、实际 Jobs、事件和命令回执。迁移 0014 新增所属表；既有 Import drafts、核心模型和 0001 迁移保持原有身份。

现有 Provider preview/grant 使用注册的 AuthoringOutboundSource。grant 先在同一事务内记录 Provider 原命令确认，再调用 source 绑定，以便 source 通过 Provider 端口检查完整已写事实；绑定失败使整个事务回滚。新增 authoring_authorizations 保存实际批准回调的会话身份。既有 Provider 账本中的 actor 按原定义仍为工作区，不能据此推断其记录了作者会话。

Worker 在当前租约、作者身份及 Policy 下请求受检 Provider。完整终态输出严格解析后，同一事务建立唯一 DraftCandidate 及 Job 终态；候选与实际原输出、完整 payload SHA 一一核验。坏 JSON、拒答和不完整输出不会产生合法候选。撤销或过期的授权在尚无派发许可时可恢复同一任务的等待批准阶段，仍需新的明确批准；已有派发许可不会自动重试。

权限恢复后的受保护读取可从 Provider 原受检产物投影此前因权限撤回而未展示的正文；这不改写原失败终态、不生成候选，也不触发新请求。安全列表及取消接口核验所属历史，只返回安全控制字段。原命令确认与当前状态分别读取。

## 数值账本与隔离运行

NumericService 建立不可变预览，保存候选、算术计划和实际运行清单。拒绝不创建 Job；批准核验当前预览和运行文件后创建独立 authoring_numeric_check Job。命令历史和检查成员关系共同约束预览数量，删除行不能释放配额或隐去已有检查。

执行记录分开保存启动许可、实际进程启动时间和实际终态。进程等待期间不持有数据库写锁；监视器回读当前权限和取消状态。重启时已有启动许可但缺少完成事实的任务保留 outcome_unknown，不重新执行。结果、原始输出哈希与 Jobs 终态在 savepoint 中原子写入，即使调用方捕获完整性异常也不留下部分结果。

NumericRuntime 使用封存的文件描述符覆盖解释器、标准库、加载器、依赖库、隔离工具、资源限制和计算入口；预览和读取只构造清单，不启动进程。仅开放固定有限算术解释器，模型输出不成为任意 Python。实际环境拒绝进入隔离时保留失败和 BLOCKED；没有宿主进程回退。

## 前端与验证边界

前端采用生成的具名 DTO，复用 Provider 冻结授权和原命令存储。学科读取权限与安全取消入口分开判断；会话、工作区或策略变化废弃旧异步学科投影。新的数值预览需要与检查身份绑定的再次确认。辅助入口保留原关闭保护，不增加主导航。

原始失败、独立反例和修后结果均保存在 progress/evidence/2026-09-16。受控本机 Provider、组件测试和纯算术测试分别证明其限定范围。本机封存执行实际被 AppArmor 拒绝，成功隔离计算和运行时资源限制未验收。生产 InputProof 仍为空；真实平台 DeepSeek、所有 M6.1 生成类型、人类数学/来源审核和教学效果均不能由此记录推定通过。

## 合成 prepare ACK 回放的被动观察

依据当前唯一规范 v3.0.7 §14、§17.3、§18.4、§20.8，507 的真实 PR 浏览器失败仍记录为原因 UNKNOWN：原 prepare ACK 回放后，详情按钮的原 10 秒 click 失败。确认回执、空列表及忙状态的截图不能证明列表请求已返回、已解析或已被当前 Hook 接受。

默认关闭的 Authoring 观察环仅由合成 E2E 同时提供显式开关和接收函数后启用。它记录 Hook 实例、操作与列表序号、ACK 接收/落盘、列表返回/接受/丢弃/错误/finally、操作结束以及 React 实际提交的忙状态和任务数量；不记录正文、对象 ID、工作区、原命令、凭据或异常文本。每个页面 epoch 最多 512 条、每批最多 64 条、一次只允许一批投递；接收器失败或停滞不等待、不重试业务操作。

原合成回放用例只在原详情 click 周围冻结观察，保持原 10 秒等待及原请求/断言。Node 使用实际 Playwright Request 对象分配唯一 ID，分别记录请求、响应状态、body 传输结束或失败；不读取 body、header 值或 query。Node 网络事件上限 2000，已投递 Hook 记录上限 1024。click 返回或抛错时同步冻结已收到记录，再以 250 毫秒上限保存诊断；保留原错误对象，诊断写入失败不改变业务断言。

浏览器 epoch 的 source_ms 与 Node delivered_ms 各自独立，禁止相减或据其拼接跨钟因果；也不猜测并发同路径 HTTP 请求对应哪个 Hook 序号。未收到的记录、页面环溢出及未完成投递均属未知，不用零条记录声称某动作未发生。requestfinished 仅证明传输结束，不能证明 JSON 校验、当前权限检查或 UI 接受。受控 Hook 和真实浏览器观察器测试验证元数据边界、容量、忙状态、原错误与冻结时点；它们不重跑原 CI 直到绿，也不构成原失败根因或产品修复的验收。

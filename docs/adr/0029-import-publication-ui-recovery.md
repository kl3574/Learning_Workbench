# 0029: Explicit Import text-block publication and original-command recovery

PRODUCT_DESIGN.md §§14, 15.1–15.3, 20.1, 20.3, 20.8 and Appendix A require exact candidate-bound approval, immutable publication, explicit human decisions, current access and a four-field publish command. This UI consumes the generated route and DraftPublishWrite provided by the real publication service. It adds no HTTP/producer state or contract fields.

The Import entry passes its actual ImportDraftSnapshot into the existing Review panel. Authoring receives no publication entry. Publication has a separate client, command ledger, Hook and panel; Review v1 command bytes and recovery remain unchanged. Existing Review/Shell close protection combines publication confirmation and unresolved-command state. No mathematics/source decision is prefilled, generated or inferred from text kind.

New intent explicitly selects a real currently read Review and then GETs that selected Review and Import draft again. It displays the exact candidate, original metadata target, current human decisions/reason, and every warning instance. Duplicate warning codes do not share checkboxes. Only after every warning instance is explicitly acknowledged are their codes deduplicated into the original four request fields. Error warnings block creation. The selected receipt revision is a displayed reading basis, not a fifth CAS field: the server revalidates the selected Review's current human history in its transaction. No global latest-Review policy is invented.

Metadata hashing is limited to the supported no-dependency text ContentBlock at revision 1. Its fixed ASCII field names, strings, one integer and string arrays have the same canonical ordering/UTF-8 representation as the Python owner; generated defaults are normalized. The Python golden includes Unicode title text, and the actual native flow independently verifies the real metadata/candidate/result hashes. This narrow equality is not assumed for Authoring, arbitrary DraftCandidate/ContentRef or the separate body hash.

Before any POST, IndexedDB must finish committing the complete original key/body and exact read basis. Conflicting originals remain stored and prevent admission. Network ambiguity retains the original; no automatic network retry or new-key replacement occurs. Explicit same-page recovery uses the original four fields/key, including deliberate server verification of a known historical ACK. A random page marker is not identity: old-page/access-generation commands are conservatively read-only because the session DTO exposes no stable actor proof. Real server access and actor ownership remain authoritative. A delayed ledger read checks the operation sequence before it may send the previously selected basis.

Access/workspace/selection changes hide protected data and discard late results; guarded storage writes abort before admission. Already dispatched server writes cannot be undone by browser unmount or permission notification. A valid saved ACK remains a historical exact ContentRef; only the separate explicit GET current supplies a separately labelled current read. The original ACK is never rewritten as current. The Import GET still reports its producer state, not a new inferred published status. The panel explains the existing whole-Import ID collision and explicit mapping path after publishing its original block.

Validation covers real IndexedDB persistence/conflict and failure, generated transport, strict DTO/ACK binding, per-warning confirmation, late results/current access, original-key recovery, explicit review selection and existing Shell close protection. One actual synthetic browser flow uses real Import/Review workers, explicit synthetic author decisions, a real server commit followed by lost response, same-key replay, actual Content bytes and GET current; no real Provider or real learning-content approval. Native screenshots/receipts can contain synthetic session reviewer identifiers and remain private until a separately verified safe evidence transformation. This slice does not implement general editing/lifecycle GET, Authoring/group/question/private-solution publication, existing-object updates or complete M6.2 acceptance.
